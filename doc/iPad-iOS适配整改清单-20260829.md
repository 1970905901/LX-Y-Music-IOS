1. **响应式基建是健全的**：`SizeView(onLayout) → windowSizeTools → useWindowSize/useHorizontalMode/useLandscapeLayout` 链路完整、旋转/分屏均能触发；三级兜底（`PageContent` 竖屏限宽 700 → `Home/Horizontal/Main.tsx` 的 `LandscapeCentered(1000)` → `LandscapeDetailLayout`/专用 Horizontal 分栏）覆盖了绝大多数页面。

## P0 · App Store 阻断项（必须先决策）

### P0-1 多任务方向组合会导致上架验证失败
- 位置：`ios/LxMusicMobile/Info.plist:134-143`
- 问题：未设置 `UIRequiresFullScreen`（即隐式参与 iPad 多任务 Split View / Slide Over），而 `UISupportedInterfaceOrientations~ipad` 只有 Portrait / LandscapeLeft / LandscapeRight，缺 `UIInterfaceOrientationPortraitUpsideDown`。Apple 规定参与多任务的 App 必须支持全部四个方向，当前组合提交会触发 `Invalid Bundle - iPad Multitasking support requires these orientations...`
- 影响：**上架被拒**；即使不上架，分屏/Slide Over 下窗口尺寸任意变化，当前 JS 布局体系也未完全按"任意窗口尺寸"设计。
- 修改点（二选一，全局决策）：
  - **方案 A（推荐，改动最小）**：`Info.plist` 增加 `UIRequiresFullScreen = YES`，退出多任务。iPad 全屏独占，方向由 `~ipad` 三个值裁决，RNN 的 `layout.orientation` 全程有效，JS 侧无需大改。代价：不支持 Split View。
  - **方案 B（保持分屏）**：`~ipad` 补 `UIInterfaceOrientationPortraitUpsideDown`，并连带完成本清单 P1-3 / P2-1 / P2-6 等分屏适配项；同时接受 RNN `layout.orientation` 在分屏窗口下被系统忽略。

## P1 · 高优先级（功能错误 / 明显体验缺陷）

### P1-1 公共在线列表列数在旋转/分屏后不更新（影响所有列表页）
- 位置：`src/components/OnlineList/List.tsx:91`（消费点 `:273` getItemLayout、`:326` numColumns）
- 问题：`const rowInfo = useRef(getRowInfo(rowType))` 把横屏双列判断固化在挂载时刻，组件存活期间永不重算；`getRowInfo()` 内部读 `windowSizeTools.getSize()`（`src/utils/tools.ts:648`）。
- 影响：该组件是排行榜/歌单/搜索/每日推荐/播放历史/专辑详情/相似歌曲等**所有在线列表的公共底座**。iPad 竖屏进入列表后旋转横屏：双列不生效、单列撑满宽屏；反向旋转同样残留。分屏拖动跨过 1.2 宽高比阈值时不切换。
- 修改点：改为响应式——`useHorizontalMode()` + `useMemo` 计算 numColumns，并仿 `src/screens/Home/Views/Songlist/List.tsx:157` 给 FlatList 加 `key={String(numColumns)}` 强制重挂载（`numColumns` 动态变更必须 remount，否则崩溃）。

### P1-2 我的列表歌曲列表同样固化列数
- 位置：`src/screens/Home/Views/Mylist/MusicList/List.tsx:71`（消费点 `:362`）
- 问题：同 P1-1 的 `useRef(getRowInfo())` 模式；且该组件被 `NewListUI.tsx:671` 的横屏分栏直接复用、不重挂载。
- 修改点：同 P1-1（响应式 + key remount），或分栏左右两栏在 `isHorizontal` 变化时用 `key` 重建。

### P1-3 分屏 / Stage Manager 下全局背景图错位
- 位置：`src/components/PageContent.tsx:36-39`
- 问题：`bgWidth = Math.max(Dimensions.get('screen').width, windowSize.width)`。分屏下 `screen` 是整块物理屏（如 1194pt），`window` 才是 App 窗口（可低至约 320pt），取 max 后背景按整屏宽铺设、被 `overflow: hidden` 裁掉右侧，`resizeMode: cover` 过度放大 → 背景突然变大变糊、不随窗口居中。
- 修改点：`bgWidth = windowSize.width`、`bgHeight = windowSize.height`。刘海/状态栏覆盖由 RNN `drawBehind` + `position: absolute` 已保证，不需要 screen 尺寸。
- 关联同源问题：`src/screens/PlayDetail/Horizontal/index.tsx:25`、`src/screens/Home/Horizontal/Aside.tsx:28` 也用 `Dimensions.get('screen')`，但两处 iOS 均提前 `return 0` 短路，仅 Android 路径使用——iOS 无需修改，列此备查。

### P1-4 评论页输入框被软键盘完全遮挡
- 位置：`src/screens/Comment/components/CommentInput.tsx:58-103`（宿主 `src/screens/Comment/index.tsx:337`）
- 问题：全项目 **0 处 KeyboardAvoidingView**。该输入框固定在页面底部 flex 布局，键盘弹出直接盖住输入框与发送按钮，iPad 竖横屏均不可用。
- 修改点：`Comment/index.tsx` 外层包 `KeyboardAvoidingView behavior="padding"`（iOS），或仿 `src/components/common/Popup.tsx:201` 用 `useKeyboard` 的 keyboardShown/keyboardHeight 手动 `paddingBottom`。

### P1-5 搜索页无键盘规避、无滑动收起
- 位置：`src/screens/Home/Views/Search/HeaderBar/SearchInput.tsx:59-70`、`src/screens/Home/Views/Search/index.tsx:241`、结果列表 `Search/MusicList.tsx` / `SearchResultList.tsx`
- 问题：键盘遮挡结果列表底部；结果 FlatList 无 `onScrollBeginDrag={Keyboard.dismiss}`（对比 `SubscribedAlbums/index.tsx:56`、`FollowedArtists/index.tsx:33` 均有收起处理）。
- 修改点：`Search/index.tsx:241` container 包 `KeyboardAvoidingView behavior="padding"`；结果 FlatList 加 `keyboardDismissMode="on-drag"`。

### P1-6 iOS 下载元数据写入被整体静默跳过（功能白丢）
- 位置：`src/core/download.ts:214`、`:298`
- 问题：iOS 直接 `return` 跳过全部元数据/封面/内嵌歌词写入，注释称"iOS 无原生模块"；但 `src/utils/nativeModules/` 的 localMediaMetadata ios 实现已存在（支持原生模块）。注释与实现矛盾。
- 修改点：移除一刀切的 `Platform` 门控，改为按原生模块可用性判断；`retryMetadata`（:298）同理。

### P1-8 下载设置页"假开关"

### P2-8 窗口尺寸变化的原生通知是死事件
- 位置：`src/utils/nativeModules/utils.ts:119-133`（iOS no-op）+ `ios/LxMusicMobile/AppDelegate.mm:4625`（UtilsModule 声明了 `screen-size-changed` 但无任何发送实现）
- 影响：`onWindowSizeChange` 在 iOS 为空实现，JS 完全依赖 SizeView 的 onLayout（当前链路可用）；但原生死事件是隐患——若未来组件在 SizeView 树之外挂载将收不到尺寸变化。
- 修改点：方案 A（P0 选 UIRequiresFullScreen）下直接删除死事件声明；方案 B 下原生监听 `UIWindowScene` coordinateSpace 尺寸变化并发事件，或复用 `tools.ts:443` 已封装的 `Dimensions.addEventListener('change')`。

### P2-9 深链 / 文件打开链路断裂

- 问题：注册了 `lxmusic` URL scheme 且 `LSSupportsOpeningDocumentsInPlace=true` + `CFBundleDocumentTypes`（lxmc/bin, Viewer），但 AppDelegate 无 `application:openURL:options:` 代理。深链与"从文件 App 打开 lxmc/bin"无任何原生入口。
- 修改点：AppDelegate 添加 openURL 代理并转发 RNN/JS；或明确移除无用 scheme/声明。

### P2-10 测试 target 必然失败
- 位置：`ios/LxMusicMobileTests/LxMusicMobileTests.m:8,29-64`
- 问题：仍是 RN 模板测试（等 accessibilityLabel "Welcome to React"，600s 超时），当前 App 经 RNN 启动无该标签，必失败；未覆盖 iPad/方向/多任务。
- 修改点：删除或重写为有效用例（验证 Info.plist 方向配置、UtilsModule 事件收发等）。
